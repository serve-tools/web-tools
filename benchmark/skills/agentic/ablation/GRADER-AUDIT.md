## Alternate fairness adjudications

The following alternate findings are valid failures against the frozen written contract: supplied `progress-fold` `highWaterMark: null`; retaining an unrelated initial event-record property in `bounded-event-channel`; and accepting malformed percent encoding in `request-target-inspector`.

`download-link` is the opposite case: the prompt permits any non-null, non-array closed object and restricts only unknown enumerable keys.
It does not require a plain or null prototype or data descriptors.
Class instances with only the named own enumerable fields, and getter-backed own required fields, are therefore legitimate inputs and need positive grader coverage.

`bounded-event-channel.watch("", listener)` is the converse: the task returns a synchronous handle but does not promise a synchronous validation failure for an invalid topic.
Remote endpoint validation is legitimate under the stated `connect`/`serve` design.
The hidden assertion requiring a synchronous `TypeError` is an unannounced timing/error requirement and must be removed unless a versioned prompt explicitly adds it and the alternate cohort re-attests.
The non-callable-listener case may remain locally synchronous because the facade itself consumes that callback.

`fixed-ping-client` likewise must accept extra response-body keys for both declared statuses.
The prompt calls only the returned facade result an exact fresh object; it does not define `{ ready: boolean }` or `{ error: "unavailable" }` as closed response bodies.
Rejecting `{ ready: true, extra: 1 }` or `{ error: "unavailable", extra: 1 }` would infer an unannounced schema restriction.
| `delayed-echo-channel` | **Prompt revision required.** The public messaging client rejects a canceled request locally and immediately after sending cancellation; the remote request signal is aborted separately. | Do not require `echo()` settlement to wait for the signal-observing remote `wait()` to settle. Require prompt exact-reason rejection plus independent eventual remote signal observation instead. |

### Delayed-echo revision evidence

The initial archived wording required canceled `echo()` to settle only after its signal-observing remote `wait()` settled.
That is not the public `connect` cancellation contract: `client/messaging/src/lib/connect.ts` installs the caller-signal abort handler, removes the client operation and posts its cancel message, then invokes the local request rejection callback with `signal.reason` without waiting for the remote handler.
`client/messaging/src/lib/serve.ts` separately aborts the active request context on cancellation, but provides no completion acknowledgement to the already-canceled client.
The final version must therefore require prompt rejection with the caller reason and independent eventual observation of the server request signal.
This is a semantic correction, not a silent fixture-tailoring change; the immutable initial prompt/source archive remains the pre-revision record and the alternate author must re-read and attest to the versioned final prompt before grading.

## Required-capability execution gate

An import-presence check does not establish execution where a task explicitly requires a package capability but its public outputs can be replicated by direct code.
Require a compiling capability-elision mutant for each such task and require that mutant to fail its grader.
This must leave the required imports in place and replace only the package-owned execution path with a direct or canned equivalent.

For the Observable tasks, wrap the mutable Observable prototype around `toArray`/`subscribe`; for framed audit, wrap `FrameDecoder.prototype.push` and `finish`.
These targeted checks are sufficient to reject the concrete retained-unused-`when` mutation that replaces its subscription with a direct EventTarget listener and equivalent abort cleanup.
Immutable ESM functions such as `deserialize` and `decodeDatagram`, plus HTTP-stream and SSE factory calls, should remain behavioral checks followed by blind saved-artifact source review.
Do not impose a general structural framework or prescribe an exact adapter topology.

## Required repair before readiness

1. Make each contract-incomplete prompt executable from public API documentation alone, including every discriminator, default, generated event/value, output shape, and authorization rule.
2. Add contract-driven checks for every missing critical behavior above, especially async error identity, abort/close settlement, cleanup exactly-once, input validation, result freshness/isolation, and canonical encodings.
3. Require real structural use only where a behavior assertion cannot prove it; do not accept superficial import checks as a substitute for behavior.
4. Re-run this audit after the prompt/check revisions, then require the two independent implementations and mutant validation before marking ready.
