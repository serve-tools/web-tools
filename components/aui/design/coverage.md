# AUI coverage plan against Base UI 1.7.0

## Scope and evidence

This is a behavior-coverage plan for a platform-native AUI component package, not a proposal to reproduce Base UI’s React API or implementation architecture.
The baseline is the published [`@base-ui/react` v1.7.0](https://www.npmjs.com/package/@base-ui/react/v/1.7.0), published August 4, 2026, and its [source tag](https://github.com/mui/base-ui/tree/v1.7.0).
The [current Base UI documentation](https://base-ui.com/react/overview/quick-start) is used only where it describes that release’s documented behavior.
The current `master` branch and its `pkg.pr.new` canaries are deliberately out of scope because they may contain breaking, unpublished changes.

Base UI is an unstyled React library, while AUI should expose natural custom-element APIs built around native HTML, `ElementInternals`, native dialog and popover/top-layer behavior, composed events, custom CSS states, and CSS positioning.
React contexts, hooks, render props, and portals are implementation choices rather than compatibility targets.
The target is observable behavior: HTML form behavior, keyboard and pointer interaction, focus, accessibility tree, geometry, state, and interoperable DOM events.

The source package has a public `radio-group` entrypoint even though the documentation navigation lists Radio only.
Accordingly, this document tracks 37 documentation families plus Radio Group and the documented utilities.
`internals/*` and other implementation-only Base UI subpaths are not component-family targets.

## Shared implementation dependencies

The following platform layers should be proven before components that depend on them.
Every listed family remains pending until its acceptance behavior is tested in an AUI package.

| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |

| Composite navigation and collection model | Model enabled/disabled items, order, active item, roving focus or active descendant, typeahead, wrapping, and mutation-safe collection updates.                                                                                                | Accordion, Autocomplete, Combobox, Context Menu, Menu, Menubar, Navigation Menu, Radio Group, Select, Tabs, Toolbar                                 | Pending |
| Native layer coordination                 | Use native dialog/popover/top-layer behavior for modality, light dismissal, focus, background interaction, and stacking. ## First proofs

The first three proofs exercise the form, composite-navigation, and overlay layers without committing to React-shaped APIs.
The initial foundation checkpoint passed 147 checks across Chromium, Firefox, and WebKit.
Tabs and Dialog are exported proofs; the full acceptance matrix below remains pending, including assistive-technology evaluation and advanced composition behavior.
The [Checkbox identity and cancellation contract](checkbox.md) follows Base UI's interaction pattern with native form association; its public export is implemented and 63 standalone Checkbox browser cases pass.
Group/parent coordination and manual assistive-technology evaluation are still separate acceptance work.
Toggle and Toggle Group are also public native-button proofs with 96 passing browser cases; [toggle.md](toggle.md) records the API, transaction, ownership, and deferred-behavior boundaries.

| Proof    | Proposed AUI semantics                                                                                                                                                      | Acceptance behaviors                                                                                                                                                                                                 | Status        |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| Checkbox | A form-associated custom control with ordinary `checked`, `indeterminate`, `disabled`, `required`, `name`, and value semantics, exposing changes as composed DOM events.    | Click, Space, label activation, disabled behavior, form submit/reset, validity, indeterminate state, accessible name and state, Enter submission behavior where native form conventions require it.                  | Partial proof |
| Tabs     | A linked tab list, tabs, and panels whose relationships are discoverable in the DOM and whose visual state remains author-controlled CSS.                                   | Arrow/Home/End navigation with RTL behavior, activation policy, disabled tabs, roving focus, `aria-controls`/`aria-labelledby`, panel visibility, nested tabs, dynamic insertion/removal, and keyboard focus return. | Partial proof |
| Dialog   | A document-level layer built on native dialog/top-layer behavior, with declarative trigger and popup relationships, author-defined DOM and CSS, and explicit close reasons. | Native modal focus and background-interaction behavior, Escape and outside-press policies, nested dialogs, menu-origin opening, detached triggers, title/description associations, and transition-safe teardown.     | Partial proof |

## Cross-cutting acceptance suite

Partial proof rows identify implemented and tested components; they do not claim the family's entire acceptance boundary is complete.
The matrix requires browser tests across keyboard-only, pointer/touch, screen-reader-facing semantics, nested components, dynamic DOM changes, native top-layer and anchored positioning, RTL, and form submission/reset/validation.
It also requires server-rendered and upgrade-timing tests if AUI supports SSR, plus CSS-customization examples that prove state can be styled without coupling consumers to internal DOM.

Upstream sources that define the reference behavior are the [quick start and component index](https://base-ui.com/react/overview/quick-start), [accessibility guidance](https://base-ui.com/react/overview/accessibility), [forms handbook](https://base-ui.com/react/handbook/forms), [release history](https://base-ui.com/react/overview/releases), and [`v1.7.0` source](https://github.com/mui/base-ui/tree/v1.7.0).
